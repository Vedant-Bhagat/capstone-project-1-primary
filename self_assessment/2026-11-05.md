## Janhavi

- **Work done this week:**
  - Wrote the `WEIGHTED_AVERAGE` tests the supervisor's feedback asked for (*"only three tests in total.
    Cover `WEIGHTED_AVERAGE` and `HARMONIC_MEAN`, and the NULL, negative, tie and text cases"*), per
    `docs/task_janhavi_weighted_average_tests.md` in the starter repository. Seven tests, numbered 12–18 in
    `sql/test_aggregates.sql` because Pranesh's `HARMONIC_MEAN` tests already hold 4–11:
    - **12** agrees with `SUM(v*w)/SUM(w)` for all 167 countries; **13** equal weights reduce to `AVG()`;
    - **14** the weighted mean of airline means equals the pooled `AVG(km)` over every route a country's
      airlines fly — the claim `janhavi_example.sql` made in a comment, now asserted, for all 167 countries;
    - **15** all-zero weights give NULL; **16** a NULL value or NULL weight makes the group NULL;
      **17** weights that cancel to zero give NULL despite real data; **18** text input in strict and
      non-strict `sql_mode`.
  - Observed every edge case before asserting it, as the task asked, rather than assuming the expected value.
  - **Finding:** in non-strict `sql_mode`, `WEIGHTED_AVERAGE` silently turns `'abc'` into 0 and counts it,
    returning a plausible wrong number (10.83) with only a warning. `HARMONIC_MEAN` returns NULL in the same
    case because its zero guard catches the 0; `WEIGHTED_AVERAGE` has no equivalent, since 0 is a legitimate
    value for it. Recorded as the real behaviour, not fixed — strict mode, the default on every version we
    test, is the defence. Also: the inline formula skips NULL rows where the function returns NULL, so the
    two are not interchangeable on dirty data (13.33 vs NULL on the `has_null` group).
  - **Checked the suite fails:** a version of the function that ignores its weights failed Tests 12, 14, 15,
    16 and 17 and the run ended in `ERROR 1644`; with the real function restored, everything passes.
