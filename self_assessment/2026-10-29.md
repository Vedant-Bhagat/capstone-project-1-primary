    finding. Found and fixed one real defect in `htmltotext.py` while reviewing it: the dropped-element depth

  - **Ran the first real ingest** — 1,289 Wikipedia articles, 18,651 chunks, real `bge-small-en-v1.5`
    embeddings — and measured everything against it.
  - **The result, which is the most useful thing the project has produced.** MariaDB's default
    `mhnsw_default_m = 6` cannot reach 98% recall@10 on this corpus at any `ef_search`; it caps at 0.937.
    `m = 16` reaches 0.9944 at the default `ef_search`, for 0.1 ms per query and 19 seconds of extra index

  - **Settled the open question from last week.** The under-return does reproduce on real embeddings — zero
    rows returned for two of nine categories at default settings. It also retired our own "7% crossover"

  - Found a bug in my own `ingest.py`: it skipped adding the vector index when one already existed, so after
    an earlier partial run the whole corpus was inserted into an indexed table — the slow path the
    specification exists to avoid, silently, because the result is still correct.
